# Streaming book layer & latency rules

- **Kraken WS v2 symbols ≠ AssetPairs wsname.** v2 uses standardized symbols (`BTC/USD`, `DOGE/USD`); AssetPairs `wsname` still reports legacy `XBT/USD` / `XDG/USD`. Subscribing with raw wsnames silently fails for all BTC/DOGE pairs (no error, just no books). Always translate XBT→BTC, XDG→DOGE per symbol part.
- **Quote "age" = PER-LEG, from the exchange's own update timestamp.** Trader's rule (and a review-found bug): a leg's age must come only from THAT pair's last exchange-timestamped update — never discounted by connection heartbeats or other pairs' activity, or a silently stalled subscription reads "fresh" forever. Consequence: quiet cross pairs legitimately age past tight windows (200ms) — stale-wait loops re-evaluating on every tick until a bounded deadline; all legs must be inside the window at the same moment. Books must be cleared on disconnect.
- **Stale → wait one tick, then SKIP; no REST in the fire path.** Executor micro-check reads the same timestamped in-memory snapshot the scanner sees (zero network). Stale quotes → wait (bounded) for the next WS update on the route's pairs and re-evaluate ONCE; still stale or stream unavailable → SKIP. Trader's explicit rule: old data is never reused, and the fire path never falls back to REST — fresh streamed data or nothing. (REST fallback is fine for display previews only.)
- **Scaled buffer must ride the whole path.** The safety buffer scales with the scanner edge (bigger stale edge → bigger margin, never a bypass). **Why:** a buffer computed at the decision gate but not passed into the executor lets routes between the small default buffer and the scaled one fire live — the executor's own preflight must enforce the exact buffer that authorized the fire.
- **Latency probe hygiene.** Module-scoped submit/ack probe on the first AddOrder is safe only because live executions are serialized by the execution lock; always disarm in `finally` or a leaked probe stamps a later unrelated order.
- **One simulator, one snapshot, one fee.** The displayed/scanned edge for an executable route must come from the executor's own depth-walk simulator on the same streamed snapshot with the same fee tier — a separate scanner implementation (own leg math, own book cache, own fee default) WILL diverge (+1.3% shown vs negative executable). Pre-fire asserts scanner-vs-decision agreement; call it a PRICING CONSISTENCY ERROR and block only when snapshot identity (marketUpdateMs) matches — a gap across different snapshots is market movement, handled by the fresh gate.
- **Route-pair fee tier must ride into the decision.** Account-default tier can understate a route's actual pair fees; re-price with max(route tier, account tier) before the adaptive decision or the buffer/floor approves on understated costs.
- Coinbase caveat: only ticker (best bid/ask) is streamed; L2 depth still REST (public level2 WS needs auth). Kraken book checksums not validated — reconnect resyncs via fresh snapshot.
